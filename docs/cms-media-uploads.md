# CMS photo uploads (local implementation)

## Routes and storage boundary

- `POST /api/admin/media`: the existing Access RS256/JWKS verifier authenticates and allowlists the editor **before** the body is read or R2 is touched. Existing origin checks remain; cross-site Fetch Metadata is additionally rejected. No anonymous/dev bypass, CORS allowance, or client-managed JWT is added.
- Upload the **raw file body**, not multipart/base64. `Content-Type` must be exactly `image/jpeg`, `image/png` or `image/webp`; compressed transfer/content encodings are rejected.
- `X-CMS-Metadata` is `encodeURIComponent(JSON.stringify({alt, caption?, title?}))`. Only `en`, `fr`, `es` keys are accepted in each localized value. `alt` is required (empty strings are allowed for decorative photos), max 500 characters per locale; optional title max 500 and caption max 2000. Combined decoded metadata is capped at 8192 UTF-8 bytes; encoded header at 24576 characters. Markup, control characters, unknown fields/locales and filenames are rejected.
- Input **and re-encoded output** are limited to 8 MiB, with actual streamed-byte enforcement/cancellation independent of Content-Length. At most 12 million pixels, 8192 pixels per dimension. Only still JPEG/PNG/WebP; APNG, animated WebP, GIF, SVG, HTML, mismatched magic/MIME and malformed containers are rejected. PNG chunk CRCs are checked. JPEG must have dimensions, a scan, scan entropy and a terminal EOI. WebP RIFF lengths and extended-canvas dimensions are checked before decoding.
- `CMS_IMAGES` performs actual decoding/re-encoding after the bounded structural preflight; a magic-header-only check would not validate compressed data. Re-encoding strips EXIF/location/ancillary metadata; only sanitized generated bytes are stored. Ordinary lossy codec damage that a decoder legitimately tolerates is not a forensic integrity guarantee. A regression explicitly rejects JPEGs whose entire scan entropy was removed, even though the local decoder tolerated and re-encoded them.
- `CMS_MEDIA` is a private R2 binding. Objects have server-generated UUID keys `uploads/upload-UUID.jpg|png|webp`; user filenames are never used. R2 custom metadata stores a small upload timestamp, not unbounded localized metadata. The returned `media` is compatible with the existing `CmsMedia` schema. Optional `title` is returned **outside** the media row because the current schema has no title field; it is an ephemeral editor label, not persisted document metadata.
- A 201 upload response returns `{media, previewSrc, title?}`. Uploading alone does not save a draft, change a content version or publish anything.
- `GET/HEAD /api/admin/media/upload-UUID.ext`: authenticated private preview, including known orphan uploads. There is no bucket listing endpoint.
- `GET/HEAD /media/upload-UUID.ext`: public only when the **currently published, visibility-projected document** contains the library row and a visible `mediaId` or direct URL reference outside the media library. A library row alone is insufficient. Each request rechecks D1, so unpublishing, hiding or rolling back removes access without a stale CDN cache.
- All media responses use `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, fixed image Content-Type and `Cross-Origin-Resource-Policy: same-origin`. Unknown/invalid media keys fail closed, never SPA-fallback. Missing D1/R2 or upload decoder bindings fail closed. No R2 public domain or direct public bucket URL should be enabled.

## Standalone UI integration

`src/admin/MediaUpload.tsx` exports:

```tsx
<MediaUpload
  language={language} // 'en' | 'fr' | 'es'; defaults to 'en'
  disabled={savingOrPublishing}
  onUploaded={(media, result) => {
    // Append to the current in-memory draft, mark it dirty; do not auto-publish.
    // Keep result.previewSrc in an editor-only map keyed by media.id.
    // Optional result.title is an editor label, not a CmsMedia field.
  }}
  onSelect={(mediaId) => {
    // Set the selected image's mediaId and copy the uploaded alt/caption if desired.
  }}
/>
```

`onUploaded(media: CmsMedia, result: MediaUploadResult)` runs before optional `onSelect(media.id)` after a successful upload. The UI offers a repeat “Use this photo” action, localized fields for all three languages, size/type hints, busy/disabled controls, accessible errors/status, cancellation on unmount and private preview. It deliberately does **not** modify AdminApp, admin styles or schema. `uploadAdminMedia(file, metadata, signal?)` uses same-origin credentials, no-store requests and URI-encoded metadata (works with accented text/emoji); it validates the response shape before returning it.

Insert `media` into `draft.media`, select the ID, then use the existing optimistic-versioned draft-save and publication endpoints. Use the authenticated `previewSrc` for all uploaded draft thumbnails and draft section previews; do not replace `media.src` in the stored draft with the private URL. The public URL intentionally returns 404 until a visible reference is published.

## Local bindings and proof

`wrangler.cms-local.toml` contains a **local-only placeholder** R2 bucket `fez-cms-media-local` as `CMS_MEDIA`, plus `[images] binding = "CMS_IMAGES"`. Neither this work nor the smoke script provisions a remote bucket/database, commits, pushes or deploys. Production `wrangler.toml` remains untouched by this task. A future authorized production integration must supply the private R2 bucket and Images binding, preserve Access variables and add `/media/*` to `assets.run_worker_first` alongside the existing admin/API guards. `/media/upload-*` was chosen to fit the schema's existing safe local image URL allowlist; unrelated static `/media` assets are left alone.

```sh
node --test tests/cms-media.test.mjs
npx tsc --ignoreConfig --noEmit --strict --target ES2022 --module ESNext \
  --moduleResolution Bundler --lib ES2023,DOM --skipLibCheck --jsx react-jsx \
  worker/media.ts worker/cms-routes.ts src/admin/admin-api.ts src/admin/MediaUpload.tsx
node scripts/cms-media-local-smoke.mjs
```

The focused tests use synthetic signed RS256 tokens, the actual Access handler/verifier, SQLite with real D1 SQL, a deterministic in-memory R2 adapter, an explicitly identified Images re-encoder test double, real upload-client requests and mounted React UI callbacks. The UI test reuses the same sibling happy-dom installation as the existing CMS admin tests; no package manifest change is made.

The smoke script uses real **local** Wrangler 4.149.0 R2/D1/Images bindings and a scratch-only worker entry with the existing JWKS-fetch test seam returning a synthetic public key. Requests still require genuine RSA signatures and the exact issuer, audience, time and allowlisted identity. It uploads and reads back all three formats; checks corruption, size, CSRF, draft privacy, publishing/hiding/rollback; then restarts the **actual production entry with no verifier seam** to prove persisted public reads and anonymous private denial. It uses a small explicit fixture validated by the real CMS schema, not concurrent site-seed data. It cleans up its servers and scratch state. Successful use of a **real operational Cloudflare Access issuer/JWKS HTTP flow**, production Images fidelity, production provider policy and storage quotas remains unproven; no production auth weakening was used to avoid that limitation.

## Verified local result

- `node --test tests/cms-media.test.mjs`: **6 passed, 0 failed**, including mounted upload UI, Unicode metadata, actual signed handler auth, privacy/rollback and empty-entropy JPEG regression.
- Scoped `npx tsc --ignoreConfig ...` command above: **exit 0**; `git diff --check`: **exit 0**.
- `node scripts/cms-media-local-smoke.mjs`: **exit 0** using real local Wrangler bindings. Returned:

```json
{"ok":true,"wrangler":"4.149.0","formats":["png","jpeg","webp"],"realLocalR2WriteRead":true,"realImagesDecode":true,"corruptJpegDenied":true,"signedAccessWithSyntheticJwks":true,"productionEntryNoSeamRead":true,"draftsPrivate":true,"publicationAndRollback":true,"remoteResourcesCreated":false,"operationalAccessIssuerHttpUnproven":true}
```

An earlier smoke exposed a genuine decoder-tolerance issue: Sharp accepted a JPEG with its entropy scan removed but the SOS/EOI headers preserved, returning 201. The server now rejects a scan that ends immediately at EOI, and **the original malformed bytes remain a 422 regression in both focused tests and the real smoke**. A separate quantization-table precision corruption passes header/dimension sniffing and is rejected by the actual Images decoder. Neither expectation was changed to 201.

Full site lint and existing backend seed-dependent tests were attempted while other agents were converting locales; they failed in those shared locale/seed paths. The media-only typecheck passes. The parent must rerun site-wide lint/tests/build and site-seed integration after those agents finish. This media proof does not claim a full-site or deployed 36-check security audit.

## Retention, orphans and cost limits

Objects are immutable and rollback never deletes them. Cancelled editor sessions, uploads never added to a draft, removed rows and older retained revisions can leave orphaned objects. Durable D1 reservations now enforce aggregate byte/object budgets and per-identity upload-attempt limits, including orphan uploads; see `cms-recovery.md`. Garbage collection remains quarantine/dry-run only. A per-file byte cap and the application budgets do **not** promise unlimited free photos or fixed monthly spend. Before production, import accounting for pre-existing objects, review actual R2/Images plan limits and costs, configure alerts and assign an operator.

Garbage collection must preserve every media URL referenced by the current draft, current published document **and all retained immutable revisions**, plus a grace period for recently uploaded objects not yet saved. Inventory the private bucket offline under authorized credentials and do a dry-run comparison first; do not delete based only on the current public document. The timestamp facilitates that grace period. No destructive cleanup endpoint is included. The CMS's existing 1000-media-row document limit is not a bucket-storage limit because history and orphans also consume storage.
